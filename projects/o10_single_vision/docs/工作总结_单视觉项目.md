# 单视觉灵巧手项目工作总结

## 文档用途与最新结论

本文用于研究生组会汇报，记录截至 2026 年 9 月 16 日的方案、实现、验证结果和后续工作。目前项目已经打通“单目摄像头识别人手动作、计算 O10 关节目标、MuJoCo 仿真验证、USB 控制 O10 真机”的完整链路。人工标定已经完成，PAPER、OK 和数字 1、2、3、4、6、8 已接入官方 SDK 预置姿态。经过三档真机限制试验，最终使用全模型关节范围、30 Hz 控制和提高后的速度限制，上机跟随效果得到现场评价“基本可以”。这一结果说明系统已从仿真阶段进入可运行的真机验证阶段，但尚缺少逐关节误差、端到端延迟和长时间稳定性等量化指标，因此不能表述为已经完成全部验收。

## 项目目标与当前范围

项目使用一个普通 USB 摄像头捕捉右手动作，将人手姿态映射到 O10 右手灵巧手。系统同时支持 MuJoCo 虚拟手和 O10 真机。当前范围包括单目视觉、单只右手、10 个主动关节、6 个模型耦合关节、官方离散手势和连续动作跟随。项目暂不包括双手协同、物体识别、抓取规划、力反馈、触觉闭环和 ROS2 控制。

## 系统流程与算法

系统首先读取摄像头图像并水平翻转，再由 MediaPipe Hands 检测 21 个手部关键点。程序用腕部和掌指关节建立正交掌坐标系，在该坐标系中计算四指弯曲、四指侧移、拇指旋转、拇指对掌、拇指弯曲、拇指跨掌和指尖接近等特征。个人标定文件把这些特征归一化到 0 至 1，随后按照 O10 模型的关节范围换算为 10 个主动关节角，并由模型耦合关系计算 6 个被动关节角。

连续动作使用几何特征映射。PAPER、OK 和数字手势使用上下文识别：程序根据四指的伸直或弯曲组合、拇指伸展状态和指尖接近关系计算连续置信度，再与官方 SDK 1.1.5 的右手预置角度统一融合。该方法保留连续跟随，同时解决拇指遮挡时仅靠关键点方向容易出错的问题。输出端使用指数移动平均进行平滑；仿真端写入 MuJoCo 关节位置，真机端通过官方 OmniHand SDK 和 USB CDC 写入关节角。

## 已完成工作

1. 建立独立项目目录 `o10_single_vision`，整理 O10 模型、配置、脚本、日志和文档。
2. 配置 Python 3.10 环境，完成 OpenCV、MediaPipe、MuJoCo 和官方 OmniHand SDK 的调用。
3. 完成摄像头读取、右手筛选、关键点绘制、无手保持和状态叠加显示。
4. 将旧版几何映射重构为正交掌坐标系，分离拇指方向与弯曲，并改用近节指骨计算四指侧移。
5. 完成七类姿态的人工标定，生成版本 4 的 `calibration_right.json`，仿真和真机自动加载同一份标定数据。
6. 接入 PAPER、OK、数字 1、2、3、4、6、8 的官方右手目标角度，并实现连续置信度和冲突处理。
7. 建立 MuJoCo 摄像头实时仿真，支持通用连续动作和官方手势目标。
8. 建立受保护的真机入口，支持只读探测、错误检查、双重解锁、机械限位、丢手停写、暂停、退出和会话日志。
9. 完成三轮真机限制调整，从低幅试验逐步扩大到全模型范围，并获得“上机基本可以”的现场结果。

## 真机控制现状

首轮真机试验采用初始位置附近 8% 全行程、10 Hz 和单周期 1% 步进，动作安全但幅度和速度明显不足。第二轮提高到 20% 工作范围、20 Hz 和 2.5% 步进，仍不能充分表现四指张合。第三轮取消以启动姿态为中心的工作包络，允许使用模型规定的完整关节范围；控制频率改为 30 Hz，速度倍率为 6，单周期最大步进为全行程的 5%，平滑系数为 0.25。四指理论完整张合时间约为 0.8 秒，跟随表现与仿真接近。

当前仍保留模型机械角度上下限、有限速度和有限步进、设备错误阻断、右手连续有效 12 帧后才能解锁、命令行 `--arm REAL_HAND` 与窗口按键 `a` 双重解锁、丢手 0.25 秒停止写入、空格暂停以及 `q` 或 Esc 退出。每次启动都先从真机实测角度初始化限制器，避免从未知姿态直接跳变。

## 当前问题与技术边界

单目摄像头不能直接测量真实深度，拇指遮挡、手掌转动和手指互相重叠仍可能使关键点抖动。官方手势目标改善了典型姿态，但处于两个手势之间时仍依赖连续融合，分类阈值还需要更多真人样本验证。O10 模型用一个主动弯曲轴带动每根手指的多个关节，因此人手末端关节的独立运动无法完全复现。

真机日志已经记录命令、回读角度和视觉置信度，但回读频率为 2 Hz，当前还没有形成逐帧命令与反馈严格对齐的误差报告。项目也没有测量从摄像头曝光到机械动作完成的端到端延迟，没有进行长时间运行、断线恢复、负载抓取和温升测试。以上内容是下一阶段的主要验收工作。

## 操作流程

1. 清空灵巧手周围的人员、线缆和物体，确认独立电源和 USB 连接。
2. 执行 `bash scripts/run_real.sh --probe-only`，只读检查设备信息、10 个主动关节和错误状态。
3. 先运行 `bash scripts/run_sim.sh`，确认摄像头识别方向、手势名称和仿真姿态没有明显异常。
4. 执行 `bash scripts/run_real.sh --arm REAL_HAND`。右手连续识别后，窗口显示 `READY - PRESS A`。
5. 按 `a` 开始真机跟随。按空格立即暂停，按 `q` 或 Esc 停止并退出。
6. 试验后检查 `logs/real_hand_session.jsonl`，保存异常动作对应的视频、截图和时间点。

## 下一阶段计划

1. 录制固定测试集，覆盖张开、并拢、握拳、OK、PAPER、数字 1、2、3、4、6、8 和连续过渡。
2. 提高关节回读频率并给视频帧、目标角和实测角添加统一时间戳，计算平均误差、最大误差、响应时间和抖动。
3. 对容易误判的姿态补采个人样本，必要时只重做有问题的标定手势，不整体推翻标定。
4. 进行分阶段稳定性试验，包括 5 分钟、15 分钟和 30 分钟连续运行，记录断线、温升和异常状态。
5. 在视觉跟随稳定后，再研究物体抓取、接触检测和触觉反馈闭环。

## 组会汇报建议

汇报时先展示系统流程和 MuJoCo 仿真，再展示官方数字手势修正前后的拇指对比，最后播放真机连续跟随。结论应表述为“单视觉到 O10 真机的闭环已经打通，典型动作上机基本可用，正在进入量化验收阶段”。同时说明单目遮挡、机械耦合和缺少力反馈是当前限制，并用下一阶段的误差与延迟测量作为后续研究重点。
